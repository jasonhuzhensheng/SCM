# 飞图 · fly photo

飞快找图的本地视觉资料库。中文名「飞图」，英文名「fly photo」。基于 SCM 0.2.7 的中文界面改版，以搜索、添加素材和预览为核心，复用原有本地检索、索引及文件管理接口。

## 使用桌面版

新版应用位于 `/Applications/飞图.app`。当前 SCM／拾光的索引任务可以继续运行，完成后退出旧版，再打开飞图。两者使用同一份素材库与模型缓存，不应同时运行；改名保留应用标识与 `~/Library/Application Support/scm` 数据目录，不重建用户素材库。

- 顶部“添加素材”：选择照片、视频或文件夹，也支持拖放。
- 搜索框：输入描述并回车；可切换画面、视频片段、图片文字与视频对白。中文画面/视频片段描述先由已安装的本地语言模型翻译成英文，再检索；界面显示英文检索词。图片文字、对白和文件名的字面匹配保留原文。翻译不可用或超时会显示提示。
- 左侧：按类型、来源文件夹和收藏筛选。
- 当前 SayPhoto 侧栏新增“AI 生成图片”和“AI 生成视频”：进入分类后只读扫描文件元数据，可暂停/继续、重新核对，并排除仅有工具名或文件名线索的疑似项。来源声明未经签名验证；没有标记或标记被移除的文件可能漏检，结果不是外观鉴定。
- 单击素材预览；方向键切换，Esc 关闭；可查看详情和在 Finder 中定位。
- 设置：切换搜索模型、管理自动添加文件夹。更多高级功能可进入原版界面；原版右上角可返回简洁版。

界面及导入响应性已调整；中文语义搜索复用本机已安装的语言模型进行翻译，没有更换图片搜索模型。更换模型仍会重建索引。收藏与最近搜索单独保存在本机。

改名版已更新侧栏、窗口标题、菜单、关于窗口、导出文件夹及中英文应用显示名。已通过生产构建、类型检查、独立素材库桌面启动（2 张测试素材）和本地签名验证。安装包：`../新版/飞图-fly-photo-20261011.zip`。


打包脚本复用已安装的同版本 SCM 运行时，叠加新界面及本地后端修复，更新 ASAR 完整性校验并进行本地签名。打包时会排除模型权重及依赖内的模型缓存，并检查产物中没有模型权重。模型独立存放在 macOS 的 `~/Library/Application Support/scm/models`（语言模型使用对应的用户数据目录），缺失时由应用按需下载；已有缓存保留。输出路径必须不存在；建议先输出到 `/private/tmp`，避免云同步目录附加 Finder 元数据干扰签名。

## 批量复制、移动与删除

在结果栏点击“批量选择”，勾选素材或全选当前结果。同一视频的多个片段按一个完整文件处理。

- “复制到…”／“移动到…”默认打开目标文件夹选择入口。已安装 Google Drive 客户端时，直接选择其同步文件夹，无需 OAuth；也支持其他本机文件夹或外接硬盘。每批创建独立文件夹，不覆盖现有文件。
- 本机传输会校验目标与源文件内容。移动仅删除软件素材库副本及搜索记录，保留导入前的原文件；本地复制完成不代表云端同步完成，云端状态请查看 Google Drive 客户端。
- “删除选中的原文件…”经确认后将原文件移到系统废纸篓，并清理素材库副本及搜索记录。右键菜单可选择删除原文件或仅删除素材库副本，预览工具栏也提供删除按钮。网盘目录的删除可能同步到云端。
- 开始复制或移动后，进度自动收起到右下侧状态栏；点击可展开详情或再次收起，不遮挡整个操作界面。退出批量选择仍保留进度，完成或失败后可查看结果，点击“完成”关闭。
- 失败文件保留并显示原因。自动同步不会重新导入未改变的已移出来源，手动重新导入仍可恢复。

设置中保留“高级：直接上传云端（OAuth）”。需自行创建 Google Cloud 桌面应用 OAuth 客户端并导入配置。授权采用 PKCE、系统浏览器、本机回调及 drive.file 范围，配置和令牌由 Electron safeStorage 加密保存。直接云端移动在上传及远端大小／MD5 校验通过后清理素材库副本。未验证真实账号授权及云端上传。

## 相似照片

## 地图找照片

点击“地图找照片”，首次分批读取素材库照片的 EXIF GPS，显示进度并缓存。拖动地图、加减缩放，单击地图或蓝色照片地点选中心，选择 0.5～500 公里的附近范围；也可直接输入经纬度。结果支持距离排序、与文字／文件夹筛选叠加、批量选择和 Drive 上传。关闭地图即可恢复普通浏览。

没有 GPS 的照片不会出现在地点结果中，不根据图片内容猜测坐标。JPEG、PNG、WebP、TIFF、HEIC/HEIF、AVIF 的元数据读取取决于原文件及当前 sharp 解码器支持；视频地点暂不读取。底图需要网络，使用 OpenStreetMap，缓存至少七天；照片、GPS 索引和距离计算都在本机，底图服务仅接收所查看区域的瓦片请求。界面最多显示 500 个可见照片地点标记，距离筛选仍包含全部带 GPS 的照片。

验证：EXIF 双字节序、半球、损坏数据、缓存更新与删除、跨日期变更线距离、底图缓存与离线降级；实际生成 JPEG 的 sharp 元数据读取；浏览器示例地点的地图及筛选交互。未对用户照片 GPS 完整率做统计。

底图规范：[OpenStreetMap Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)。

## 本地检测数据库与后台索引

二维码、条形码和图片文字查询读取 `~/Library/Application Support/scm/library/image-detections.sqlite`，使用 SQLite WAL。搜索不再启动逐图检测或读取整个文字 JSON；已完成结果立即显示，每三秒更新搜索结果和待处理数量。

- 启动后自动核对已有图片；导入完成的新图片立即进入后台队列。
- 文件系统事件加周期性核对记录大小、mtime、ctime。未变化的图片复用结果；新增、修改文件才运行检测。
- 常驻、低优先级原生进程一次读取图片，同时检测二维码和常见一维条形码。旧 JSON 缓存按文件签名迁移；仅二维码缓存完整的图片仍需补齐条码结果。
- OCR 沿用已有后台识别流程，启动时和识别完成时同步文字到数据库，不额外重复 OCR。修改图片会使旧文字命中失效。
- 删除和移动同步移除数据库记录；检测完成时复核文件签名，避免迟到结果复活已删除或修改的记录。
- 可以在二维码／条形码结果栏暂停和继续后台检测；暂停状态与已完成结果跨重启保留。首次全库后台检测仍需时间；未完成、失败和文件核对进度均会显示。
- 检测失败有限次延迟重试，失败不当作“未检测到”。程序退出时停止原生检测器并关闭数据库。

查询示例：`二维码`、`条形码`、`图片文字`、`图片文字：订单编号`。图片文字按 OCR 实际内容匹配，忽略大小写、空白及全半角差异。以上结果显示完整缩略图，不以语义相似图片补位。模糊、遮挡、未完成 OCR 或识别错误可能导致漏检。

修改原生检测器后运行 `npm run build:qr`，再构建打包。验证：`node test/detection-index.test.js`、`node test/detection-search-ui.test.js`。

## 大库索引队列优化（2026-10-11）

后台检测的待处理任务使用 SQLite 部分索引 `detection_pending`，队列领取和是否继续运行均直接查待处理项，避免反复扫描已完成图片。同名导入文件在本批次内记住下一个编号，保留原来的命名顺序，避免重复从 `(2)` 查到最后。

验证：`node test/index-scaling.test.js`（613,167 条合成记录的查询计划及任务命中、25,000 个同名文件的线性查找次数）、既有检测数据库、导入顺序、复制及索引性能测试。子流程基准不能代表整库完成时间；AI 推理仍逐图运行，未更换模型、降低画质或跳过搜索向量。线程数试验波动较大且独立 ONNX 基准退出时有原生清理异常，因此没有修改推理线程默认设置。

## 速度优先索引（第二轮）

- 用户选择速度优先后，通过一次性设置 `requestedIndexModel: "siglip2-base-patch16-224"` 请求启动切换。窗口加载后沿用已有断点迁移流程，完成转换再启动文件夹同步；失败保留请求供下次重试，不直接改写旧向量的模型标识。
- UUID、完整长哈希及纯长时间戳文件名不再运行文本模型，写入对齐的零文本向量。图片向量照常计算，原始文件名仍可精确搜索，有描述性的文件名保留文本推理。启动修复和切换缓存复用均识别这种有意的零向量。
- 模型转换从固定每 25 项全量保存，改为按批量大小约 40 次保存；慢任务最多间隔五分钟触发检查点，最后仍完整保存。
- 前台导入或模型转换期间，后台二维码/条码推理自动让出 CPU；完成后自动继续，不改变用户暂停设置。

本机 21,821 条已保存记录中有 20,836 个纯 UUID 文件名。SigLIP-2 单张 CPU 推理小样本为约 104–190ms；只代表这一阶段，不代表整库完成时间。保留 CLIP 模型和旧索引文件，可通过设置切回。批量 CLIP 推理测试出现约 0.02 余弦偏差，未采用。

验证：`node test/fast-index.test.js`、`node test/delta-switch.test.js`、`node test/library-store.test.js`、`node test/detection-index.test.js`、`node test/index-performance.test.js`、`node test/index-scaling.test.js`、导入排序与搜索回归，以及前端构建。

部署验证：两张独立测试图片通过真实 Electron/模型转换，2/2 成功、旧 CLIP 文件保留、UUID 零文本向量正确、描述性文件名文本向量非零，启动请求在转换完成后清除。已安装到 `/Applications/SCM 拾光.app` 并启动用户选择的快速模型转换；原应用备份为 `/Applications/SCM 拾光-before-fast-index-20261011.app`，切换前索引备份位于工作区 `新版/切换前索引备份-20261011`。大库转换在应用内继续运行，磁盘主索引仅在完成后切换模型。

大库实测补充：首次转换在第 424 项后大量失败，已从备份恢复完整 CLIP 索引。随后增加严格转换模式：出现错误立即保留原索引，成功行仅保存为未完成缓存；重试复用成功行，未完成缓存不能走瞬时切换。转换优先读取资料库内副本，减少对原始路径权限、挂载和云盘状态的依赖。回归：`node test/migration-atomic.test.js` 覆盖第 424 项失败、原索引保留和断点恢复。

## 搜索状态与常用中文词

画面搜索在模型加载失败时明确报错，不再把暂不可用显示为零结果；模型转换期间支持搜索已完成的部分。「裸体」「护照」等完整常用词可直接翻译，无需调用语言模型；句子和否定描述仍按完整原文翻译。翻译拒答不再被当作检索词。已验证翻译、否定描述不被替换、切换期间报错、构建及类型检查；尚未确认真实素材库中这两个词的命中率。

## 边建索引边搜索

「画面描述」在模型转换及导入期间可搜索已完成的图片。新模型向量使用独立的内存搜索视图，只有维度正确、有限且非零的向量进入结果；原索引仍在转换全部成功后才切换。查询在当前图片处理结束后优先执行。排名在独立进程完成，首次传入已处理行，以后只传新增行，不为每次搜索重写整个索引。

界面显示当前可搜索范围及结果不完整提示，保留已显示结果，每 5 秒刷新；新导入的命中图片会补充素材信息。部分结果不会混入旧模型的视频片段向量，也不会用尚未处理图片的文件名补足结果。视频片段索引仍需对应模型处理完成。

真实 Electron 验证：12 张临时生成图片，在导入 2/12 和模型转换 2/12 时均通过渲染器 IPC 返回命中；旧索引保持到全量转换成功，完成后恢复完整搜索。已验证进程间显式进度对象、增量排名缓存、零向量排除、模型切换竞态与查询队列优先级。

### Apple 照片图库

侧栏的“连接整个照片图库”通过 PhotoKit 请求 macOS 照片访问权限。选择允许全部照片后，读取系统照片图库中的照片、视频原片（含可访问的隐藏照片、连拍），不需要手动导出。飞图保存本地副本；iCloud 原片按需下载，照片编辑后的效果与 Live Photo 动态部分不单独同步。

运行期间每分钟检查新增资产，退出后暂停，下次启动自动继续。按 PhotoKit 资产 ID 保存导入完成进度，失败资产不会标记完成，自动重试；重复内容交给现有内容去重。不会反向修改或删除 Apple 图库。仅有部分照片权限时明确提示，整库范围受系统授权和可访问状态限制。已建索引部分可以即时搜索，搜索结果每 5 秒刷新。

验证：`node test/apple-photos.test.js`，`node test/live-search.test.js`，`node test/live-query-priority.test.js`。本地开发前运行 `npm run build:photos-bridge`；`package:simple` 自动编译并嵌入原生桥及权限说明。首次真实授权必须由用户在 macOS 系统提示中完成。

macOS 必须经 LaunchServices 启动（`open -n /Applications/飞图.app`），不可用 `subprocess.Popen` 直接启动 `Contents/MacOS/SCM`，否则 TCC 将照片请求归到启动方，可能直接拒绝且不弹窗。用户明确要求连接时可用 `open -n /Applications/飞图.app --args --connect-apple-photos`，仍由 macOS 展示授权提示。

### 人物分组（macOS 27+）

左侧“人物”→“扫描 / 更新人物”，使用苹果本地 FaceGroupAnalyzer 自动分组；可以给人物命名、按姓名搜索，并选择一个或多个人物查看相关照片和视频。点击“锁定所选人物全部素材”可批量保留当前已识别文件，锁定后沿用原有删除/移动保护。新导入的文件需再次扫描并锁定，不会自动删除未识别素材。

视频约每5秒抽帧，最多120帧；长视频间隔更大，短暂出现、模糊或侧脸可能漏检。分组也可能有误，命名和锁定前可查看对应素材。关闭面板后已启动的扫描仍继续，点击暂停会等待当前文件/分组完成后保存检查点。独立索引位于素材数据目录的 `people/`，不修改原文件或现有搜索索引。此功能建立应用自己的分组，不读取苹果“照片”中已有的人物命名。

开发时先执行 `npm run build:face-groups`。本机原生测试：`node test/face-groups-native.test.cjs <人物甲照片> <人物乙照片> <人物甲视频>`，需允许苹果推理框架运行；脚本创建临时测试库，不扫描真实图库。可通过 `FACE_GROUPS_BINARY` 指定安装包内原生程序。Node 管理逻辑回归：`node test/face-groups.test.cjs`。

### 人物合并与纠错

- 合并：选中同一人的多个组，在“合并后保留人物”选定目标，点击“合并所选人物”。保留目标姓名，其他组名可继续作为搜索别名。
- 纠错：点击人物卡片“检查 / 移出人脸”，逐张查看照片/视频帧中的脸，勾选误识别项后点击“移出所选人脸”。这些脸组成新组，可继续命名或合并。
- 移出只调整人脸归属，不删除原文件、不解除锁定。合照或视频还有其他人脸留在原组时，该文件仍显示在原组。先暂停识别并等待任务完成，再修改分组。
- 手动归属在重启和后续自动分组中保留；文件内容/签名或人脸位置发生变化时，需要重新核对。首次编辑备份为人物目录中的 `people.json.before-manual`。
- 回归：`node test/people-corrections.test.cjs`；真实苹果接口测试：`test/people-corrections-native.test.cjs` 接收两个人物图片及人物甲视频三个路径，创建临时素材库。完整Electron运行时已验证；本地Node需安装package.json声明的Sharp依赖。

### AI 优选排序

素材排序支持“AI 优选：质量高到低”和“AI 优选：质量低到高”。切换方向保留当前评分与暂停状态，不重新启动评分任务。选择后按当前搜索/筛选范围内的照片分批进行本地苹果 Vision 美感与拍摄质量评分，并映射为 0–100 分，分数越高越靠前。支持暂停、继续及重试；未评分/失败项和视频放在后面，不代表它们质量差。需要 macOS 15+，评分仅供选片参考。

评分独立保存在 `photo-quality.json`，按模型版本、文件大小、mtime、ctime 和 inode 核对，不修改原照片及搜索索引。开发时先执行 `npm run build:photo-quality`；本地复用运行时打包脚本会编译并包含原生评分程序。
